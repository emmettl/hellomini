# 0.10 development validation

18 October 2026. This records development evidence, not a published release approval.

## Implemented scope

Chooser stores up to 40 service destinations locally, including service kind and optional port. It validates destinations, ignores stale discovery callbacks, reports browsing/connection state, and opens connections through macOS. Saved entries contain no credentials. Connections menu actions provide a keyboard route; Save Service uses Command-S.

Tiny-screen mode retains 2× as its default and offers a saved 1.5× comparison setting. Purist stays exactly 512 × 384. Common sheet content and form widths now follow the logical desktop width. Impossible instruments is an optional Activity Monitor effect, disabled by default, with a real CPU needle, explicitly decorative particles, a numeric accessible value, and reduced-motion/pause/visibility gates.

## Automated coverage

`make check` passed on the development Mac (192 Swift test executions across debug and release-mode products; no compiler warnings). It runs formatting, Swift tests, release-mode Print Monitor tests, Python CI/release/tap/resource checks, and a development build. New tests cover destination persistence/deduplication/invalid ports, stale discovery callbacks, scale persistence and invalid values, 1.5× geometry, Purist invariants, instrument animation policy, and Chooser action bounds across all six themes at compact sizes.

## Live development preview

On the development Mac, using the Aqua theme:

- Saved and forgot a temporary SSH destination with an explicit port; checked validation feedback and cleared the test fields afterward. No connection was initiated.
- Inspected Chooser field/button accessibility labels and hostname-to-port Tab traversal. Background-window controls appeared later in the Tab sequence; a complete focus-order audit remains open.
- Opened Activity Monitor with the keyboard launcher; paused and resumed sampling with Command-P.
- Switched between 2× and 1.5× through Control Panel and inspected the resulting layout. Restored 2× afterward.
- Enabled Impossible instruments, observed a real CPU sample matching its accessible percentage and visible numeric summary, then restored the effect to off.

## Remaining evidence

Development-monitor screenshots do not establish Wokyis legibility. The physical comparison below supports retaining 2× for the tested setup. The earlier Mini display-change and display-sleep results, and the unresolved full-system-sleep check while CI/recorder assertions are active, remain documented in [Wokyis validation](WOKYIS_VALIDATION.md). ## Physical Wokyis comparison — 18 October, 22:48 onward

Source `9433f35` was built and copied to `/private/tmp/hellomini-010-check/Hello Mini.app` on the Mini, separately from Homebrew. The running executable was verified over SSH. Standard Screen Sharing retained the physical Wokyis at 1280 × 720, 60 Hz throughout the scale comparison.

The user observed Classic at their normal viewing distance. At 2× they reported that project names and the smaller Updated text were readable, although Control Panel obscured part of the list during the first question. For the 1.5× comparison Control Panel was closed and the Print Monitor list brought forward; the user reported **“1.5× is too small.”** This supports retaining **2× as the Wokyis default** for this user/setup; it is not a universal visual-acuity result. The 1.5× option remains an explicit space-versus-size choice for other displays.

Both presets reflowed without losing the scale controls. Native View → Enter Full Screen worked. No physical panel resolution change or cable hot-plug was performed in this comparison.

The Mini still had active CI work and the MotionStudies recorder's `caffeinate -is` assertion. Full system sleep was not retried with those blockers present.

Additional physical-console checks:

- Restored the saved scale to 2× and closed Control Panel after comparison.
- Launcher arrow keys and Return opened Find File. The Option-Command-M chord did not visibly open the launcher through this viewer; remote shortcut forwarding remains inconclusive.
- At 2× the Projects sheet showed Add, Token, Remove and Done fully within the display. Escape dismissed it without modifying projects or credentials.
- `pmset` recorded display-off at **23:04:15 CEST** and display-on at **23:05:10**. Remote pointer input restored the display. The same development process (PID 72401) survived; the clock and desktop input recovered, and Wokyis remained online at 1280 × 720. This is display sleep, not full system sleep.
- Command-F5 did not start a VoiceOver process on the Mini. No spoken VoiceOver walkthrough is claimed; the remote viewer exposes only its shared-screen container, not the Mini's underlying accessibility tree.

No new application defect was established by these checks. GitHub access/rate-limit errors were displayed during Print Monitor refresh; they do not constitute successful live-provider validation.

Post-wake launcher arrow navigation opened Activity Monitor; it displayed live CPU/process samples on the Mini. The development preview was left at Classic, 2×, full screen; the Homebrew app bundle was not replaced.
