# 0.11 development validation

18–19 October 2026 (Europe/Zurich). Development scope; 0.10.0 remains the published release.

## Changes and limits

Inactive accessory contents are disabled for keyboard navigation and collapsed out of the accessibility tree. Each inactive window exposes an activation button; Window, launcher and Dock remain available. Activating a background window takes one click before interacting with its contents. Finder operation sheets focus the destination name; dismissal restores the selected item or toolbar, after AppKit's responder transition. Pending restoration cancels when the accessory deactivates or disappears.

Physical windows is off by default. A bounded, finite settling deformation follows a title-bar drag; rounded themes settle more softly than square themes. An explicit keyframe trigger prevents SwiftUI from coalescing the settling impulse away. It does not animate saved origins, alter pointer coordinates, or run a continuous renderer. Extra silliness, Reduce Motion, scene activity and desktop suspension gate it.

Finder has one session-only Undo slot for successful New Folder, Rename and atomic same-volume Move. A successful Copy clears it. Receipts check device/inode, type/mode, size, modification/change timestamps and a bounded directory-tree snapshot (10,000 entries, depth below 64). Unsupported/oversized snapshots leave no receipt. Parent identity and exclusive rename protect occupied original names; new-folder Undo uses rmdir and refuses non-empty folders. Changed items stop Undo and clear the receipt. No Redo, copy removal, replacement or cross-volume moves are included. Metadata checks are conservative and are not a transaction against hostile concurrent path changes.

DesktopModel and desktop effect definitions now live in dedicated files rather than DesktopView and SystemSounds. Version and display-comparison documentation was refreshed.
