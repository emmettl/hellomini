# 0.13 validation

19 October 2026 (Europe/Zurich).

## Scope and recovery

Scrapbook collection names can be changed without merging an existing collection. Explicit multi-selection intersects selected IDs with the visible query/collection/favourite/archive scope. Batch filing, favourite/unfavourite and archive/restore save atomically before updating the model. Collection removal keeps scraps. One session-only Undo Filing receipt checks expected organisation and collection names before restoring metadata; note contents and OCR results are preserved. New library membership or conflicting organisation changes refuse Undo rather than overwrite newer state. The on-disk library/archive formats remain version 2.

Finder Redo follows successful Undo of New Folder, Rename or same-volume Move. Rename/Move record a fresh inverse fingerprint after Undo; Redo uses the existing exclusive rename path. New Folder checks parent identity and exclusive creation. Redo captures a fresh Undo receipt. A new successful operation clears Redo; invalid receipts clear the affected action. No multi-step history, copy removal, replacement or cross-volume Move is included. These conservative metadata checks are not filesystem transactions against hostile concurrent path changes.

Paper shuffle is a finite 0.33-second themed keyframe rotation, off by default. Extra silliness, Reduce Motion, accessory activity and desktop suspension gate its visible motion. It does not change saved geometry or introduce a continuous renderer.

Shared MiniSheetFocusRestoration observes native sheet-end, key-window and update notifications and waits for a main-queue event barrier. Deactivation/dismantling cancels queued work. Finder and Scrapbook provide their own focus targets; the separate 250–300 ms delays are removed. Scrapbook transfer, filing, OCR coordination and shelf-row code now live in separate files. The Vision recognizer remains separate from its scheduling coordinator.

## Automated evidence

The full check suite covers guarded Redo round trips for all three supported operations, a second Undo after Redo, changed sources, occupied dangling-link destinations and replaced parent directories. Scrapbook tests cover rename, multi-selection scope, failed saves, archive/restore, collection-removal recovery and preservation of OCR/text while undoing filing. Complete-library fixtures retain archived picture bytes and existing OCR across legacy upgrade and portable backup/import, including a blocked migration backup that must leave the original index and images unchanged.

The focus fixture verifies deferral until sheet-end, request coalescing and cancellation. Populated batch controls and filing forms are checked across all six themes at Purist and 2× logical sizes, including horizontal bounds and a minimum usable shelf viewport. Native sheets retain scrolling for longer forms. Final release preparation repeats strict lint, all Swift tests, release-mode Print Monitor tests, Python CI/release/tap/resource checks and the build on committed source.
